# Design runtime

Injected page runtime for the embedded browser's design tools.

- Page-side functions (`createElementInspector`, `installDesignRuntime`, `readDesignPageSignals`) are serialized with `.toString()` and run inside the guest page. Their bodies must stay self-contained: they may use only their parameters and page globals.
- Page → host traffic is `window.postMessage({ [bridgeKey]: 1, events })`; the embedded browser's fixed guest preload checks `event.source`, the page protocol (`file:` without host, or a signed `nibi-html://` preview), the namespace key and the UTF-8 size cap, then forwards it with `sendToHost`. Host → page traffic is the fixed `DesignRuntimeCommand` set over `executeJavaScript`. Page scripts can forge events, so every host-side parser (`parseDesignRuntimeEvents`, `parseDesignPageInfo`, `parseDesignPageSignals`) caps strings and arrays (`DESIGN_PAGE_LIMITS`); the result only ever becomes a user-visible, removable element reference, and a forged source path can only fail to match.
- The runtime owns only a projection (selection boxes, style previews). The page reports the selection; the host mirrors it and owns CSS variable previews, the active variant and selection pins, and re-sends them after every reinjection. There is no page-side write path and no raw CDP.
- The fixed guest preload also forwards a trusted Cmd/Ctrl + Z (Shift = redo) as `EmbeddedBrowserWebviewChannels.DesignUndoShortcut` only when the key target is not an editable page control; the host source writer owns the undo/redo stack, requires the file to still equal the previous write, and recognises its own writes so live reload does not refresh the page it just wrote.
- `sourceEdit.ts` (parse5, host-side only, never serialized into the page) maps a selected element back to the local HTML source by its path of tag / index / sibling count plus id and class, and rewrites only that element's `style` attribute or text, or one `:root` variable value. Any mismatch returns null and nothing is written.
- The host write is `IFileService.writeDesignSourceFile({ workspacePath, path, expectedContent, content })`: the realpath of `path` must stay inside `workspacePath`, only `.html`/`.htm` are accepted, reads are strict UTF-8 with a 4 MB cap, the write only proceeds while the file still equals `expectedContent`, and replacement goes through a same-directory temp file plus `rename`. A failed or stale check never produces a success state in the UI.
